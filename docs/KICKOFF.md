# انطلاقة مشروع TrackEcom

هذا الملف هو نقطة البداية لكل من ينضم إلى الفريق: ما الذي نبنيه، ولماذا هو أفضل مما هو موجود، ومن يعمل على ماذا، وكيف نعمل على Git، ومن أين نبدأ اليوم.

## 1. الفكرة

**TrackEcom** منصة يُدير منها البائع الجزائري متجره الإلكتروني بالكامل في مكان واحد: من لحظة وصول الطلبية، إلى تأكيدها، ثم شحنها مع أنسب شركة توصيل، ثم تتبّعها مباشرة، وصولًا إلى استلام أموال الدفع عند الاستلام (COD).

ليست مجرد أداة لإنشاء الطرود وطباعة الملصقات، بل هي **نظام تشغيل للمتجر الإلكتروني الجزائري**.

**الفارق الأقوى هو النقطتان 1 و2**، ويجب أن تكونا محور التسويق. لذلك نجمع البيانات اللازمة لهما (حالات الطلبيات، أسباب الرفض، سجلّ الأرقام) **من المرحلة الأولى**، حتى لو لم نبنِ النموذج إلا في المرحلة الثالثة.

## 3. التقنيات

- **الويب:** Next.js + TypeScript + Tailwind، مع دعم كامل لاتجاه RTL للعربية.
- **الـ API:** NestJS + PostgreSQL + Prisma، وRedis + BullMQ للمهام الخلفية (مزامنة شركات التوصيل والإشعارات).
- **الموبايل (المرحلة 3):** React Native.
- **البنية:** Monorepo يضم `apps/web` و`apps/api` و`packages/ui` و`packages/carriers`، مع Docker وGitHub Actions.

يُثبَّت هذا القرار رسميًا في ADR-0001 (#8).

## 5. قواعد العمل على Git

1. **الفرع الافتراضي للعمل هو `dev`.** لا أحد يدفع (push) مباشرة إلى `main` أو `dev`.
2. لكل Issue فرع جديد من `dev`، باسم مثل:
   `feat/13-web-skeleton` أو `fix/42-cod-rounding` أو `chore/11-docker-compose`.
3. **كل Pull Request يستهدف `dev`**، ويذكر رقم الـ Issue في الوصف (`Closes #13`).
4. الـ PR يحتاج مراجعة من الشخص الآخر قبل الدمج في `dev`.
5. **الدمج من `dev` إلى `main` يقوم به Samir فقط**، عند إصدار نسخة مستقرة. الاستثناء الوحيد هو فروع `hotfix/*` للإصلاحات العاجلة.
6. Commits صغيرة ورسائل واضحة بالإنجليزية (`Add orders list page`).

التفاصيل الكاملة (حماية الفروع، القوالب، التسميات) موجودة في `docs/WORKFLOW.md` (PR #64).
